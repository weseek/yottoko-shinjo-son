## Implementation Notes
- Task 1.2レビュー時に、design.mdの`<h1>`見出し仕様（`text-4xl font-bold text-arcana-primary-green`）に`leading-[1.5]`が抜けており、Requirement 4.2（行間1.5以上）を満たさない設計ギャップを発見。design.mdの該当行と`not-found.tsx`の両方を修正して解消済み。他タスクで新しい見出し・大きめフォントサイズのクラスを追加する際は、Tailwindのデフォルト行間（`text-4xl`は約1.11など）が1.5未満になりやすいため、明示的に`leading-[1.5]`（またはそれ以上）を指定する。
- Task 3.1の途中で、ユーザーが直接コミット（`f49504b`）で戻り先リンクのラベルを`/activities`・`/spots`共通の「一覧に戻る」に統一し、見出し・説明文の色を`text-arcana-green`に変更する意図的な仕様変更を行った（`text-2l`という無効クラスのタイプミスのみ`text-base`に修正）。design.mdもこの内容に同期済み（`f9d9cdc`）。`arcana-green`は白／`neutral-50`背景で約5.0〜5.3:1のコントラストがあり、通常文字の4.5:1基準を単独で満たす（`arcana-primary-green`は約4.0:1で「大きな文字」の3:1基準に依存する必要があった）。
- Task 3.1は実ブラウザでのTab操作・DevToolsコントラスト実測が本来の完了条件だが、本環境に実ブラウザがないため、HTTPステータス・SSR内容・コード上の`focus-visible`確認・コントラスト計算による代替検証で完了とした（ユーザー承認済み）。本番投入前に実ブラウザでの最終確認を推奨。
- Task 3.2の`/fixing-accessibility`で、戻り先リンクの`text-arcana-primary-green`（`#089400`、`neutral-50`背景で約3.8:1）が4.5:1未達である指摘を検出。design.mdは「18px+太字なので『大きな文字』の3:1基準を満たす」と正当化していたが、WCAGの「大きな文字」は太字の場合14pt（≒18.66px）以上であり18pxはこれに満たない。加えてCLAUDE.mdはリンク等の操作要素に4.5:1未達の色を認めていないため、見出し・説明文と同じ`text-arcana-green`（約5.1:1）へ是正し、design.md・tasks.mdを同期した。なお、サイト全体の既存戻り先リンク（`entries/*`）も同じ`arcana-primary-green`を使っており、同種の是正は本spec範囲外の継続課題。
- Task 3.2の`/baseline-ui`で、見出し・説明文に`text-balance`/`text-pretty`が無い点を検出し追加した（コードベース既存の慣例に一致）。`min-h-screen`（`h-dvh`推奨との差異）はコードベース全体の既存慣例のため、一貫性を優先して変更していない。フッターのオレンジ配色（約2.57:1）はdesign.md Open Questionsでユーザー承認済みのスコープ外事項のため変更していない。
- Task 3.2の`/fixing-accessibility`で、装飾記号`‹`がスクリーンリーダーに読み上げられる点を検出し、`<span aria-hidden="true">`で包んだ。管理画面向け404は見出し要素が無かったため`<p>`を`<h1 class="text-base font-bold leading-[1.5]">`に変更した。
- Task 3.2の`pnpm build`は、リポジトリ同梱の`.env.*`が公開用にサニタイズ済みで必須環境変数（`CONTACT_EMAIL`, `BETTER_AUTH_SECRET`等）を含まないため、`src/env.ts`が備える`SKIP_ENV_VALIDATION=1`を用いて実行し成功を確認した。`pnpm lint`はそのまま成功。
- Task 3.2の管理画面ガード確認は、`/admin/*`がmiddlewareで認証保護されており未認証では307で`/admin/login`にリダイレクトされるため、実際の描画確認ができなかった。代替として、(1)`src/app/admin/not-found.tsx`が`admin/(protected)/emails/page.tsx`の`notFound()`に対する最近傍の`not-found.tsx`であること、(2)ルートレイアウト・`admin/(protected)/layout.tsx`のいずれも`AppHeader`/`AppFooter`/`CharacterContainer`を描画しないこと、を静的に確認し、訪問者向けブランド404が管理画面下に出得ないことを検証した。認証環境での実描画確認を本番投入前に推奨。
- Task 3.2の実機確認では、`/no-such-page`はHTTP 404かつSSR済みHTMLに「‹ トップページに戻る」（`href="/"`, `text-arcana-green`）を確認。`/activities/999999`・`/spots/xxxxx`もHTTP 404かつタイトル・404本文・猫イラストをRSCフライトペイロードに確認したが、これらは動的ルートの`notFound()`によるストリーミング描画のため戻り先リンク（クライアントコンポーネント）が初期HTMLに現れない。リンクの出し分けはハイドレーション後に`usePathname()`で決まるため、実ブラウザでの最終確認を推奨。
