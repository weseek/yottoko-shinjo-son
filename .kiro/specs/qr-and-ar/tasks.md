# Implementation Plan

- [ ] 1. プロジェクトセットアップと基盤準備
- [x] 1.1 依存パッケージのインストールと設定
  - AR エンジン（mind-ar）、3D レンダリング（three）、QR コード生成（qrcode.react）のパッケージを追加する
  - three.js の型定義（@types/three）をインストールする
  - GLB ファイル（.glb, .gltf）を Git 管理対象外にする .gitignore 設定を追加する
  - _Requirements: 1.1, 2.1_

- [x] 1.2 共有型定義とダミーデータの作成
  - AR ターゲット設定、3D モデル設定、撮影結果、AR シーン状態の型定義を作成する
  - デモ用ページ状態の型定義（画面遷移: ランディング → AR → プレビュー）を作成する
  - 検証用のダミースポットデータ（名前・説明）を定義する
  - 2つの GLB モデル（ヒメッコ、ラバーダック）の設定データ（URL・表示名・スケール）を定義する
  - デモ用ターゲット設定（.mind ファイル URL）を定義する
  - _Requirements: 4.5_

- [x] 1.3 (P) マーカー画像と .mind ターゲットファイルの準備
  - 検証用マーカー画像を用意する（特徴点が豊富で認識しやすい画像）
  - MindAR のオンラインコンパイラまたはプログラマティック API でマーカー画像を `.mind` ファイルにコンパイルする
  - コンパイル済み `.mind` ファイルとマーカー画像を `public/assets/targets/` に配置する
  - _Requirements: 1.3, 1.4_

- [ ] 2. AR シーンコンポーネントの実装
- [x] 2.1 MindAR と three.js の初期化・ライフサイクル管理
  - Client Component として AR シーンコンポーネントを作成し、SSR を無効化した動的インポートで読み込む
  - MindAR の画像トラッキングシステムと three.js レンダラーを初期化する処理を実装する
  - カメラストリームの取得とカメラ許可状態のハンドリングを実装する（許可要求 → 許可 / 拒否の分岐）
  - `.mind` ターゲットファイルのロード処理を実装する
  - コンポーネントのアンマウント時にカメラストリームと MindAR インスタンスを確実に停止・破棄するクリーンアップ処理を実装する
  - MindAR の start/stop が非同期であることを考慮し、二重起動を防ぐガード処理を入れる
  - AR シーンの状態遷移（idle → camera-requesting → initializing → scanning → tracking → error）を管理する
  - _Requirements: 1.1, 1.5, 1.6, 1.7_

- [x] 2.2 画像トラッキングと GLB モデル表示
  - マーカー画像の認識イベントを購読し、マーカー検出時に状態を tracking に遷移する処理を実装する
  - マーカーロスト時に状態を scanning に戻す処理を実装する
  - three.js の GLTFLoader で GLB モデルを読み込み、マーカー位置にアタッチする処理を実装する
  - モデル設定（スケール・回転オフセット）をモデルに適用する
  - モデルの切り替え（props 変更）時に既存モデルを破棄し新しいモデルを読み込む処理を実装する
  - _Requirements: 1.2, 1.3, 1.4, 4.4_

- [x] 2.3 写真撮影機能（Canvas 合成）
  - WebGL レンダラーに `preserveDrawingBuffer: true` を設定する
  - 撮影ボタン押下時にカメラ映像（video 要素）と AR レンダリング（WebGL canvas）をオフスクリーン Canvas に合成する処理を実装する
  - 合成結果を PNG 形式の data URL としてエクスポートし、撮影結果（画像データ + 撮影日時）としてコールバックで親コンポーネントに渡す
  - 撮影中の状態管理（capturing 状態への遷移と復帰）を実装する
  - _Requirements: 3.1_

- [ ] 3. UI コンポーネントの実装
- [x] 3.1 (P) ミニ導線画面の作成
  - スポット名と簡易説明を表示するランディング画面を作成する
  - 「撮影する」ボタンを配置し、タップ時に AR 撮影画面への遷移をトリガーする
  - カメラ許可ダイアログの前に文脈を提供する役割を果たす（AR 撮影の説明テキスト）
  - WCAG AA 準拠: 最小フォントサイズ 14px、行間 1.5、コントラスト比 4.5:1 以上を確保する
  - _Requirements: 2.2, 2.3, 2.5_

- [x] 3.2 (P) 撮影写真プレビュー・保存・共有画面の作成
  - 撮影した写真のプレビューを全画面で表示する画面を作成する
  - 保存ボタン: data URL から `<a download>` を利用して端末にダウンロード保存する機能を実装する
  - シェアボタン: Web Share API (`navigator.share()`) を呼び出す機能を実装する。`navigator.canShare()` でサポートを判定し、非対応時はシェアボタンを非表示にする
  - 撮り直しボタン: AR 撮影画面に戻る機能を実装する
  - _Requirements: 3.2, 3.3, 3.4, 3.5, 3.6_

- [x] 3.3 (P) QR コード生成・表示コンポーネントの作成
  - qrcode.react を使用して、スポット ID を含む URL の QR コードを Canvas に描画するコンポーネントを作成する
  - QR コード画像のダウンロード機能を実装する（Canvas から `toDataURL()` で画像化 → ダウンロードリンク生成）
  - QR コードのサイズをプロパティで指定可能にする
  - _Requirements: 2.1, 4.2_

- [x] 3.4 (P) 3D モデル切り替え UI の作成
  - 利用可能なモデル一覧をボタンまたはセグメントコントロールで表示する UI を作成する
  - 選択中のモデルを視覚的にハイライトする
  - モデル選択変更時にコールバックで親コンポーネントに通知する
  - _Requirements: 4.4_

- [ ] 4. 検証ページの統合
- [x] 4.1 デモページのルート作成と画面遷移管理
  - `/ar/demo` ルートにページコンポーネントを作成する（`"use client"` 指定）
  - 画面遷移（ランディング → AR → プレビュー）の状態管理を実装する
  - AR シーンコンポーネントを SSR 無効の動的インポートで読み込む
  - ダミーデータと初期モデル選択の状態を初期化する
  - 認証なしでアクセス可能であることを確認する
  - _Requirements: 4.1, 4.5, 2.4_

- [x] 4.2 全コンポーネントの結合と動作確認
  - ランディング画面 → AR シーン → 撮影 → プレビュー → 保存/シェア/撮り直し の一連のフローを結合する
  - モデル切り替え UI をランディング画面または AR 画面に配置し、モデル変更が AR シーンに反映されることを確認する
  - QR コード表示をランディング画面に配置し、QR ダウンロード → スキャン → 同ページに遷移するフローを確認する
  - ローディングインジケーター（MindAR 初期化中、GLB ロード中）を表示する
  - AR 状態（scanning / tracking）に応じたステータス表示を追加し、動作確認結果を視覚的に判断できるようにする
  - _Requirements: 4.3, 4.6_

- [ ] 5. エラーハンドリングと UX ポリッシュ
- [x] 5.1 カメラ許可・ブラウザ互換性のエラーハンドリング
  - カメラ許可拒否時のガイダンスメッセージ（ブラウザ設定でカメラを許可する手順）を表示する
  - WebGL 未対応ブラウザ向けの AR 利用不可メッセージを表示する
  - getUserMedia 未対応ブラウザ向けのカメラ利用不可メッセージを表示する
  - MindAR 初期化失敗、GLB ロード失敗、.mind ファイルロード失敗時のエラーメッセージとリトライ導線を実装する
  - _Requirements: 1.7, 1.5_

- [x] 5.2 (P) レスポンシブ対応とアクセシビリティの調整
  - スマートフォンの画面サイズを主対象としたレスポンシブレイアウトを適用する
  - 撮影ボタンを十分な大きさで配置しタップしやすくする
  - 全画面でのフォントサイズ・行間・コントラスト比を確認・調整する
  - 各ボタンに適切な aria-label を付与する
  - _Requirements: 1.5_

- [ ] 6. クロスブラウザ検証とテストコード
- [x] 6.1 型定義と状態遷移のユニットテスト
  - AR シーン状態遷移ロジックのテストを作成する
  - Web Share API サポート判定ロジックのテストを作成する
  - QR コード URL エンコーディングのテストを作成する

- [x]* 6.2 実機での動作検証チェックリスト
