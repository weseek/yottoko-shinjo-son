# Requirements Document

## Introduction

管理画面（`/admin`）に ID/パスワード認証を導入する。現在すべての管理画面ルートが認証なしで公開されているため、Better Auth ライブラリを使って最低限のセキュリティを確保する。管理者ロールを持つユーザーが管理画面からメンバーアカウントを作成・管理できる構成とし、共通固定トークン方式からの移行を行う。

## Boundary Context

- **In scope**: `/admin` 配下の全ページの認証保護、ログイン/ログアウト、管理者によるユーザーアカウントの作成・削除・一覧
- **Out of scope**: 訪問者向けのアカウント登録・ログイン、OAuth/SNS ログイン、パスワードリセットメール（α版スコープ外）
- **Adjacent expectations**: `/api/admin/*` の API ルートも同様に認証保護されること。既存の next-admin による CRUD 機能は認証導入後も変更なく動作し続けること。

## Requirements

### Requirement 1: ログイン

**Objective:** 管理者として、メールアドレスとパスワードでログインしたい。そうすることで、権限のあるユーザーのみが管理画面にアクセスできる。

#### Acceptance Criteria

1. When 未認証ユーザーが `/admin` 配下の任意のページにアクセスしたとき、管理認証システムはログインページにリダイレクトしなければならない。
2. When 正しいメールアドレスとパスワードを入力してログインを実行したとき、管理認証システムはセッションを発行し、管理画面トップページへ遷移しなければならない。
3. If 誤ったメールアドレスまたはパスワードを入力してログインを試みたとき、管理認証システムはエラーメッセージを表示しなければならない。
4. The 管理認証システムはパスワードを平文で保存してはならない。

---

### Requirement 2: セッション管理

**Objective:** 管理者として、ログイン後のセッションが適切な期間維持され、安全に管理されることを望む。

#### Acceptance Criteria

1. While ログイン済みセッションが有効なとき、管理認証システムは再ログインなしに管理画面の操作を継続できなければならない。
2. When セッションが期限切れになった後にページへアクセスしたとき、管理認証システムはログインページへリダイレクトしなければならない。
3. The 管理認証システムはサーバーの再起動後も有効なログインセッションを維持しなければならない。

---

### Requirement 3: 管理画面・API ルートの保護

**Objective:** 管理者として、管理画面のすべてのページと API ルートが未認証ユーザーからアクセスできないようにしたい。

#### Acceptance Criteria

1. The 管理認証システムは `/admin` 配下のすべてのページを認証保護しなければならない。
2. The 管理認証システムは `/api/admin` 配下のすべての API ルートを認証保護しなければならない。
3. If 認証なしで保護された API ルートへリクエストが送られたとき、管理認証システムは 401 または 403 レスポンスを返さなければならない。

---

### Requirement 4: ユーザー管理

**Objective:** 管理者として、管理画面からメンバーアカウントを作成・削除・一覧できるようにしたい。そうすることで、村側の担当者など新しい管理メンバーを自分で追加・管理できる。

#### Acceptance Criteria

1. When 管理者がメールアドレスとパスワードを入力してユーザー作成を実行したとき、管理認証システムは新しい管理者アカウントを作成しなければならない。
2. When 管理者が既存ユーザーの削除を実行したとき、管理認証システムはそのアカウントを削除しなければならない。
3. The 管理認証システムは登録済みユーザーの一覧を表示できなければならない。
4. If すでに登録済みのメールアドレスでユーザー作成を試みたとき、管理認証システムは重複エラーを表示しなければならない。
5. The 管理認証システムは、最後の1名の管理者アカウントの削除を拒否しなければならない。

---

### Requirement 5: ログアウト

**Objective:** 管理者として、管理画面からログアウトできるようにしたい。そうすることで、操作後にセッションを安全に終了できる。

#### Acceptance Criteria

1. When 管理者がログアウト操作を実行したとき、管理認証システムはセッションを無効化し、ログインページへリダイレクトしなければならない。

---

### Requirement 6: 初期管理者アカウント

**Objective:** 運用担当者として、システム初回導入時に最初の管理者アカウントをセットアップできるようにしたい。

#### Acceptance Criteria

1. The 管理認証システムは、初期管理者アカウントを作成するための手段（シードスクリプトまたは環境変数）を提供しなければならない。
2. If 管理者アカウントが1件も存在しないとき、管理認証システムは初期セットアップ手順を示すメッセージを表示しなければならない。
3. When 本番デプロイパイプライン（Cloud Build）が実行されたとき、デプロイパイプラインは DB マイグレーション後・サービス公開前に初期管理者シードを冪等に実行しなければならない。これにより本番環境に管理者が1名も存在しない（ログイン不能）状態を作ってはならない。
4. The 初期管理者のパスワードは、ソースコードやプレーンな環境変数ではなく Secret Manager 等の機密管理機構を通じて注入されなければならない。
